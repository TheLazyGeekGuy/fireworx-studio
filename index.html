≋ P0 Buffer · User & Card Banks Data21 Scalars · Data20 Structural + Readback

FireworX Studio connects via bidirectional Web MIDI (DIN or RTP/mioXL). After two matching P0 buffer reads ("Live · verified"), parameter tweaks use short Data21 writes while structural changes use complete Data20 images with comparison read, readback, and an ~8.9 s settle window.

Two-read P0 synchronization

Connecting never overwrites the unit with a stale browser draft: two identical P0 replies (F0 00 20 1F 00 40 45 00 00 F7) are required before live editing unlocks.

Enforced structural settle

Complete 2,745-byte P0 structural writes enforce an ~8.9 s quiet window without competing GET, CC, or Clock messages, coalescing gestures safely.

Zero backend, 100% local

All presets, libraries, and MIDI journals remain in your browser profile. No cloud account, telemetry, or external server is ever contacted.

Documented alpha boundaries & pending qualification
  • Protocol target is FireworX OS 2.00+; not a certification of every firmware version, MIDI interface, or memory card.
  • Controls external hardware via MIDI/SysEx only; does not process audio or receive hardware level/gain-reduction/CPU telemetry.
  • User/Card STORE backs up the destination slot and verifies readback; complete hardware qualification and retention across power-off remain pending.
  • The DSP percentage (1–108%) is an additive software estimate, not a hardware DSP counter or overload guarantee.
  • Global I/O SETUP → CTRL read/write and global BPM readback are not established; packed User dumps require expanded per-preset reads for editing.

Key questions

Before you start.

Does FireworX Studio risk overwriting my hardware presets when I connect?+

No. Connecting reads P0 twice and waits for two identical responses ("Live · verified") before enabling live edits. It never automatically transmits an old draft from browser storage upon connection, and temporary P0 editing is strictly separate from persistent User/Card STORE.

How do I connect my FireworX via Web MIDI?+

Connect both MIDI directions (Computer Out → FireworX In AND FireworX Out → Computer In). Open the editor in a Chromium browser (Chrome, Edge, Brave, Opera), allow MIDI/SysEx access, and open MIDI / Buffer if you need to pick your input/output ports or SysEx Device ID explicitly.

Can I use FireworX Studio without a FireworX plugged in?+

Yes. Without MIDI permission or hardware, you can build signal chains, edit all 38 algorithms and modulation links, import/export .syx and .json files, organize local banks, and generate seeded variations.

Why is there an ~8.9 second pause after adding, moving, or deleting a block?+

Structural edits (changing the matrix, adding/removing blocks, or changing unverified routing fields) require sending a complete 2,745-byte Data20 P0 image. The FireworX hardware needs at least 8 seconds after wire transmission to settle before accepting new GET, CC, or Clock messages.

How does the Seeded Randomizer protect my signal chain?+

You can lock any block you want to preserve, choose between Parameters, Structure, or Blocks + Routing variations, and set a deterministic seed. Variations respect instance quotas, valid routing rules, feedback/Insert protections, and your configured DSP budget ceiling before you preview or apply them.

Where are my presets, libraries, and MIDI logs stored?+

Everything stays locally in your browser profile (LocalStorage and IndexedDB) scoped to the site origin. Nothing is uploaded to any server. Use the disk icon and Library export tools to keep portable .json and .syx backups on your computer.

Get Started with FireworX Studio

FireworX Studio works directly in your browser with zero installation, both online and offline, or from a local Vite development server.

🌐
1. Instant Browser Access (Recommended)

Open the editor in Chrome, Edge, Brave, or Opera. Connect both MIDI In and MIDI Out to your FireworX (OS 2.00+), allow Web MIDI / SysEx access, and wait for "Live · verified".

Open editor ↗
⚡
2. Run Locally via Vite Dev Server

Clone the repository and run the local development server on your machine:

git clone https://github.com/TheLazyGeekGuy/fireworx-studio.git
cd fireworx-studio
npm ci
npm run dev
Then open http://127.0.0.1:5173/editor/ in a Web MIDI compatible browser.
